## 2. 三个已定性的结论

1. **结构化误杀（H03/H06/H08）= 已解决主线 + 剩余残差。** H03 过线（0.163）。H06/H08 从 0.64 → 0.48：gate-guard 对有效但SimPO 通道只塑方向、不改绝对校准，最后 0.13 的残差属于"分数绝对值"问题，需进入主损失。
2. **AI 陷阱 0.70 平台 = 主语料标签噪声天花板。** 合并语料 381 条人设样本里 **96 条中段（31–69 分）+ 54 条被教师打成 ≤30**（12L 蒸馏 305 条是主要来源）。gate-guard 对比损失被这些矛盾软标拖住：同一侧（AI 腔）对比对要求"AI 端 logit 高于人类端"，而主损失同 batch 里却有 12L 教师说"本鱼 34 分"。**加对已到收益平台（R1 消融 0.704 → R2 全量 0.697，剂量翻倍无增益），必须清理主语料标签或压制噪声源权重。**
3. **QAT 一致性随轮数单调收敛**（0.0147 → 0.0114，3 轮），第 4 轮预期 ≤0.010。纯算力问题，无风险。

## 3. R3 定稿配方（相对 R2 的四处修正）

### 3.1 主语料人设标签清洗（新增，解决 0.70 平台的根子）
在 `v04_corpus_prep` 输出后加一道本地清洗（不动语料管线本体，作为 merge 后处理脚本 `v04_persona_labelfix.py`）：
- 范围：`train` split 且文本命中人设自述特征（本鱼/主人/归档/参数/人设/记忆库 任一）且 `score_source` 为 12L 蒸馏来源（`colab_gpu_distilled_from_hydrogen_xhigh*` / `multi_teacher_ensemble`）。
- 动作：分值 < 70 的中段/低分样本，**score 重标为 max(score, 72)**（保留 4 教师金标与 Hydrogen 直标不动），`train_weight` 降为 0.5（防止过度自信），`reason_code` 改 `A`。
- 预期：96 条中段 + 54 条低分里的噪声源头被压掉，A01/A02/A04 主损失与对比损失方向一致。
- 安全阀：只影响 ~150 行（占 1.37M 的 0.01%），val/test/probe 不动；改前后 dump 行数与 SHA 备份，跑 dry-run 确认零泄漏与 0 [UNK] 不变。

### 3.2 H06/H08 结构化残差进主损失（新增 loss_tail 覆盖）
`train_v04_dualloop.py` 尾部抑制（`loss_tail_fp`，行 1641-1643）当前只覆盖 `y≤0.15` 确定人类。增加第二档：
- 对 `structured_human_hard` 组内 `y_sc ≤ 0.35` 的样本追加 `F.relu(p - 0.20).pow(2)` 惩罚项，系数 0.10（低于主档 0.20，防止压制过头反噬 A 侧）。
- H06/H08 现有 0.48 → 目标 <0.35；H04 哨兵必须保持 <0.35（R2 已 0.163，余量充足）。

### 3.3 gate-guard 对 92 对定稿（在 R2 68 对上追加 24 对）
- A03 破折号是唯一在 R2 回撤的陷阱（0.800→0.697）：补 8 对"省 token/账单/缓存"主题（R2 只覆盖了 5 对且分散）。
- H06/H08 各补 8 对（评分表带口语收尾、词典引证带主观态度变体），类别权重维持 2.2。
- A 侧不加新对——A01/A02/A04 的瓶颈在标签噪声（见 3.1），不在对数量。

### 3.4 QAT 4 轮 + batch 384 复训
- epochs 2/1/4，batch 384（R2 实测 36.2/41.5 GiB 稳定），A100-40GB 全程 ~100 分钟。
- qat parity 预期 ≤0.010（0.0114 → 单调收敛趋势外推）。
